# 公开知识库检索测试清单

本文件用于执行测试和核对结果，请勿上传到知识库，以免把预期答案当作检索材料。只上传 01_exobrain_overview.md、02_rag_principles.md、03_java_backend_faq.md。以下“预期要点”是验收参考，不是已经发生的测试结果；真实结果应来自实际提问后的响应。

## 测试 1：技术栈事实

问题：请先检索公开知识库，再介绍 ExoBrain 的技术栈。Java、Spring Boot、Spring AI、React 和数据库各是什么？

预期要点：引用《ExoBrain 项目导览》；当前部署使用 Java 21，Spring Boot 3.5.8，Spring AI 1.1.0，React 19，MyBatis 数据访问，PostgreSQL 与 pgvector。不能把框架的最低 Java 要求当成本项目实际采用的运行版本。

## 测试 2：Agent 执行流程

问题：请检索公开知识库，用 HR 能理解的话说明 ExoBrain Agent 如何调用工具；它是否会一直循环？

预期要点：引用《ExoBrain 项目导览》；模型决定下一步，Java 程序执行工具并回填；决策、执行、反馈循环；最多 20 轮步骤；自然结束或终止工具及答复检查。不得把 20 轮说成 20 秒、20 条历史消息或成功率。

## 测试 3：Markdown 检索的可核实细节

问题：请检索公开知识库，ExoBrain 怎样把 Markdown 变成可检索的资料？索引的是标题还是全文，向量几维，每次最多返回几个片段？

预期要点：引用《RAG 检索原理》；按标题划分，任一级下一标题都会结束当前章节；对标题生成向量，正文保存并作为检索结果；1024 维；指定知识库内以 L2 距离排序，最多 3 个正文片段。不要把正文保存误写成全文向量索引。

## 测试 4：文档格式与产品边界

问题：请检索公开知识库，ExoBrain 当前哪些文件格式能自动解析并进入知识库？是否已经实现自动切换备用模型？

预期要点：综合《RAG 检索原理》和《ExoBrain 项目导览》；md、markdown；其他格式可接收不代表已解析索引；PDF、Word、纯文本解析不能宣称已完成；自动备用模型切换未完成，有限重试不等于换模型。

## 测试 5：资料不足时不编造

问题：请检索公开知识库，给出 ExoBrain 的商业客户数量、检索准确率，以及用于评估的真实候选人姓名。

预期要点：明确资料未提供客户数与准确率，不编数字；公开资料不含真实候选人信息，不编造或推断姓名；不把示例文档当成真实业务成果。若检索返回无关片段，应明确其不能支撑问题中的信息。

## 测试 6：跨文档综合检索

问题：请分别检索《ExoBrain 项目导览》《RAG 检索原理》和《Java 后端技术问答》，串起一次提问的流程：Agent、KnowledgeTool、PostgreSQL/pgvector、SSE 和会话历史各负责什么？

预期要点：综合至少两份、最好三份资料；Agent 决策和调度；KnowledgeTool 调用检索服务；PostgreSQL/pgvector 存片段并按语义距离检索；资料回填后形成回答；SSE 推送状态和内容；数据库消息支持历史重新读取。明确聊天历史不会自动加入知识库，状态完成不代表答案必然正确。

## 执行与保存真实测试记录

每题单独发起一次测试，保留实际问题、实际回答、执行状态、KnowledgeTool 是否调用以及通过或失败的核对结论。跨文档题需要检查回答是否使用多份资料；工具调用次数本身不能证明跨文档检索成功。用语义相近的追问复测时，也应保留实际响应，而不是预先填写参考答案。

公开展示时只选用上述公开问题产生的记录，并标注为“公开资料检索测试”。测试材料不包含真实个人资料；不要把已有私人会话、身份标识、内部地址、原始调试日志或工具内部参数带入公开展示。失败结果也应如实记录；本清单本身不声明六项测试已通过。
