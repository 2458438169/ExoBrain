# ExoBrain 工程案例（2026-10-19 版）

本文用「问题 → 方案 → 验证结果」的结构讲三个真实的工程案例，全部来自本仓库的实现与测试记录。
核对日期：2026-10-19。文中耗时与用例数量都是当次真实输出，不代表长期性能承诺。

## 案例一：重复点击发送，会不会跑两次

**问题**：网络慢的时候用户会连点发送，或者请求其实已经到服务器但响应丢了。如果后端每收到一次就执行一次，
会出现两条用户消息、两个模型调用、两笔费用，甚至两条不同的回答挂在同一个问题上。

**方案**：把「一次提问」变成带唯一键的提交意图，服务端按 `(身份, 会话, 幂等键)` 去重。

- 前端为每个「新的提问意图」生成一个键，重试与重连复用同一个键，只有用户明确问下一个问题才换键。
- 提交在一个事务里完成：写用户消息、固定历史快照、创建运行记录、入队。同一个键再次到达时不再新建运行，
  而是返回原来那次运行的 `runId` 与状态。
- 同一个键但内容不同则直接拒绝，避免拿旧结果冒充新请求。

**验证结果**：真实 PostgreSQL 集成测试断言同键并发只产生一次运行、返回同一个 `runId`；同键不同内容返回冲突。
真实浏览器里丢弃首个响应后手动重试，数据库仍然只有一个运行、一条用户消息、一次模型调用。

**边界**：这只保证「同一会话的同一提交意图最多执行一次」，不是对外部调用的 exactly-once 承诺。
工具调用、模型请求本身仍然可能被重复发出，系统只保证结果写入与终态是唯一且受校验的。

## 案例二：点了取消，模型又迟到返回

**问题**：取消是个协作式动作。已经发出去的模型请求无法撤回，几秒后它可能仍然返回一段完整答案。
如果不加约束，这段时间里运行可能已经被标记为取消，而答案又被追加到会话里，用户看到「已取消 + 又有回答」。

**方案**：把「请求取消」和「运行终态」分开，并给每一次执行加 fencing 校验。

- 运行中的取消只登记 `cancel_requested`，检查点在下一个步骤前停止发起新的工具或模型调用，最终记为
  `CANCELLED / CANCELLED_BY_USER`。
- 每次领取任务都会让 `fencing_token` 前进。写答案时必须同时满足「任务行仍是 RUNNING」「fencing 未被接管」
  两个条件，答案消息与 `answer_message_id` 在同一个事务里写入；条件不满足就整笔回滚，迟到的内容一个字都不留。
- 取消与完成竞争、取消跨过心跳周期、重启遗留的 RUNNING 都有各自的判定，不会互相顶替。

**验证结果**：真实 PostgreSQL 用例覆盖三条路径：运行被标记中断后写答案必须抛出租约丢失并回滚；正常运行时
答案与关联同事务落库；租约被接管后旧执行写不回任何内容。另有一条 18 秒模型调用、10 秒租约的用例，取消后
终态为 `CANCELLED`，迟到响应不追加答复。

**边界**：取消不撤回已经发出的外部请求，也不承诺「立即停止」。界面显示的是「正在取消」，直到运行状态
真正变成终态。

## 案例三：一个任务的行锁，为什么会连累别的任务

**问题**：租约续期、心跳、写消息都是对数据库的写操作。当某一行被一条慢事务锁住时，续期会卡在锁上。
如果多个运行共用同一个后台线程，一个任务的锁等待就会拖住所有任务的心跳，别的运行被误判成中断。

**方案**：把「锁等待」变成有界、可放弃的动作，并且每个运行独立。

- 每个租约使用自己的单线程调度器，心跳续期走独立连接 + 独立事务 + `SET LOCAL lock_timeout`，
  被锁挡住只会跳过这一拍，不会把运行判成租约丢失。
- 执行检查点如果被锁挡住，先在预算内重试；预算耗尽后用一次**不加锁的读**确认状态、fencing 与租约期限。
  确认不了就停止执行，绝不再发起新的模型调用。
- 摘要心跳（用于判断「重启遗留的 RUNNING」）也改成有界写，写完再确认一次，最终确认之后不再执行任何
  可能长时间阻塞的数据库写入。

**验证结果**：真实 PostgreSQL 用例固定复现这三类场景：A 的消息事务持锁 16 秒时 B 的 22 秒模型调用仍正常完成；
检查点在锁等待中租约到期必须抛出租约丢失；摘要心跳被锁挡住时按预算放弃而不是无限等待。

**边界**：这些是正确性与成本保护，不是吞吐优化。行锁冲突频繁时，运行会更快失败或降级为「中断」，
而不是排队等待更久。

## 从这三个案例能看出什么取舍

- 优先保证「不骗人」：宁可把一个运行标成中断，也不写回一个无法证明归属的结果。
- 所有结论都带可复核的证据：数据库断言、真实 HTTP 请求、真实模型调用。
- 没有做的不要装作做了：真正的逐字流式输出、跨实例自动迁移、外部调用 exactly-once 都不在本版范围。
