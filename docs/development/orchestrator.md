# 主 Agent 开发交接单

适用于用户把优化工作交给一个主 Agent，由主 Agent 自行调用子 Agent 的协作方式。主 Agent 负责全过程交付，子 Agent 承担边界明确的实现、测试或审查。

本交接单组织的是**开发协作**，不要求为 ExoBrain 产品增加多 Agent 运行功能。任务内容与优先级见[开发总指南](README.md)，数据与接口约定见[共享契约](contracts.md)。

## 1. 用户可以直接复制的启动提示词

~~~text
请在 ExoBrain 仓库中执行优化开发。你是负责交付的主 Agent，我授权你使用当前环境提供的子 Agent 能力，自主创建、分派、跟进和复用子 Agent，无需让我逐个分发任务。

先阅读 docs/development/orchestrator.md、docs/development/README.md、docs/development/contracts.md，以及 docs/development/tasks/ 下的 01–08 任务书。按依赖顺序完成两阶段任务；第一阶段是验收检查点，通过后继续第二阶段。若我另行限定范围，以我的要求为准。

你负责计划、任务拆分、共享文件所有权、接口协调、代码审查、集成与最终回归。子 Agent 返回后，你要核验代码和实际测试证据，再接受交付；从分派持续推进到已交办任务完成。

保留游客免登录与账号登录，管理员也必须隔离其他账号的私有知识库、助手和会话；保留现有预览、删除、模型管理和历史功能。评测、引用和执行记录必须真实，不得编造工具调用、通过结果或效果指标。

统一更新 README 和相关工程文档，并推送到 https://github.com/2458438169/ExoBrain.git。先核对远程映射，不向上游推送，不强推，不覆盖无关修改。主 Agent 负责最终集成与发布；生产部署按实际收到的授权执行，已有授权无需重复确认。

执行中简洁汇报里程碑、实际阻碍和下一步。最终给出完成范围、提交、测试与评测证据、部署状态及仍未解决的限制。
~~~

主 Agent 应实际使用环境提供的子 Agent 工具，不把普通聊天任务创建工具当作内部子 Agent 调度器。若环境没有可调用的子 Agent，明确说明并自行顺序执行能完成的工作；不能声称已分派给不存在的子 Agent。

## 2. 主 Agent 的职责

1. **核实起点。** 读取适用仓库说明，确认实际工作目录、分支、提交、远程和未提交修改；核对指南所列基线与当前实现的差异。已有完成项不重复做，后续修改不覆盖。
2. **建立任务台账。** 在拟新增的 `docs/development/deliveries/status.md` 中记录编号、负责人、工作目录、起始/依赖提交、允许修改文件、状态、交付提交和证据位置。状态可为待开始、执行中、待审查、返工、验收通过、受阻。
3. **管理依赖与契约。** 让生产者先明确数据字段、源位置规则和迁移边界，再交给消费者。发生变更时同步任务书、契约、共享夹具和相关子 Agent。
4. **分配并保留工作。** 子 Agent 处理独立模块时，主 Agent 可整理集成、核对权限/迁移、验证已交付部分；持续跟进真实进展，避免仅创建任务后停止工作。
5. **核验交付。** 子 Agent 的“完成”先进入待审查；主 Agent 检查 diff、接口兼容、真实测试输出及依赖，验收后才标记通过。
6. **统一提交与发布。** 主 Agent 是最终集成负责人。08 子 Agent 可以实现 CI、文档和部署配置，但不成为第二个独立发布负责人。

常规实现选择、子 Agent 数量、任务拆分与调度由主 Agent 决定。仅在确实缺少必要信息、凭据或授权时提出具体问题，同时继续不依赖该条件的工作；不能把已有授权的操作反复交回用户确认。

## 3. 调度顺序

并发度以当前环境实际容量为准，包含主 Agent 自己。若环境总容量为 4，可由主 Agent 加最多 3 个子 Agent 起步；不把 8 项任务一次性全部启动，也不假设每个子 Agent 自动拥有隔离工作区。

| 波次 | 子 Agent 工作 | 主 Agent 的推进与验收 |
| --- | --- | --- |
| A | 01 并发修复、02 评测基线、08 基础 CI 可以并行 | 核实基线与文件所有权，协调测试配置；先审查 01 |
| B | 01 验收并合入后做 03；02 保留旧基线并准备对比；空闲人员继续 08 | 固定 03/04 契约。旧策略基线必须可复现，不因切到新代码而丢失 |
| C | 04 可先用约定夹具做界面，03 合入后完成真实联调；02 跑候选对比 | 验收 01–04 与 08 当批交付，完成第一阶段集成；分配空闲子 Agent 做只读审查 |
| D | 第一阶段通过后，05 执行追踪与 06 持久导入可在文件边界允许时并行 | 协调共享类型、文档视图和迁移，08 持续维护 CI/文档 |
| E | 05 验收后做 07；可参考 06 的租约经验，不要求共用队列表 | 审查对话幂等、权限重新校验、副作用中断与新旧 worker 切换 |
| F | 子 Agent 修复审查反馈、补缺失证据，08 完成本批工程文档 | 在同一最终提交上完成必要回归、汇总实际结果，统一推送并处理已授权部署 |

第一阶段通过后继续已交办的第二阶段；用户明确只要求第一阶段时到该范围完成即可。某项依赖真实外部服务而受阻时，应保存已完成工作、明确未执行的验证，并推进其他独立任务；不能以假数据绕过验收。

可复用已空闲的子 Agent 处理下一项任务或独立审查。跨任务复用时重新交代基线、依赖与文件所有权，不能让它继续沿用上一项的修改范围。额外拆分由主 Agent 统一登记并受同一并发上限约束。

## 4. 工作区、共享文件与提交规则

- 先确认子 Agent 实际运行目录。优先使用工具支持的隔离工作区；隔离分支从主 Agent 指定的已接受提交开始，尤其不能误从指向上游的默认分支开始。
- 独立工作区内，子 Agent 可提交自己负责的变更，由主 Agent 审查后集成。**共享目录模式下，只由主 Agent 执行 Git 暂存、提交、切分支和集成操作**；子 Agent 汇报文件变更与检查结果，避免把别人的半成品一起提交。
- 共用目录时明确文件所有权；涉及同一文件的实现串行接续，或由指定所有者应用其他子 Agent 提交的补丁建议。不能认为“修改不同函数”就没有并发覆盖风险。
- 不在共享工作目录里执行会覆盖别人工作的 reset、clean、stash、rebase 或大范围恢复。删除/移动文件前核验目标属于当前任务。
- 根 README、共享契约、`pom.xml`、前端依赖/锁文件、Nginx 与部署配置的最终写入由主 Agent 协调。08 可受委托修改指定文件，但依赖版本和路由变化不能在不同分支各定一套。
- 测试必须对应稳定代码。共用目录有其他子 Agent 正在改相关文件时，不把此时的一次通过当成最终版本证据；集成后重新执行本批必需检查。
- 迁移按任务编号独立编写，应用顺序由主 Agent 根据真实依赖确定。已经应用的迁移不能被另一任务改写。
- 子 Agent 使用合成/可公开测试数据。分派消息只提供必要配置引用，不广播生产密钥、会话令牌、其他用户文档或私有登录材料。

更细的共享文件顺序沿用[总指南的文件所有权表](README.md#5-接口先行与文件所有权)。进入下一位修改者前，主 Agent 明确通知上一位停止写入，并说明已集成的起点。

## 5. 主 Agent 向子 Agent 下发任务的模板

下面是模板，分派前填入实际值；不能把尖括号占位符原样当成已经确认的信息。

~~~text
你的任务是 ExoBrain 优化 <编号/明确子范围>，向主 Agent 汇报。

工作目录：<实际绝对路径；注明独立工作区或共享目录>
起始提交：<SHA>
已接受依赖：<任务编号、提交及契约/夹具位置>

必读：
- docs/development/README.md
- docs/development/contracts.md
- docs/development/tasks/<对应任务书>
- <相关前置交付记录>

负责修改：<明确目录/文件>
共享文件规则：<哪些可以改，哪些向主 Agent 提交补丁建议>
Git 规则：<独立工作区可提交 / 共享目录仅主 Agent 提交>
范围外事项：<本项不承担的其他任务、主分支推送和生产发布>

按任务书实施并运行与变更相关的检查。遇到接口冲突、依赖缺失或文件归属冲突，向主 Agent 报告，同时继续独立工作。不要覆盖其他成员修改，也不要自行扩大任务或产生未登记的嵌套分派。

交付：
1. 完成范围和修改文件。
2. 实际起始/交付提交；共享目录模式说明尚未提交。
3. 执行过的测试命令、通过/失败/跳过/未执行及证据位置。
4. 接口、迁移、回滚影响，以及下一任务需要的内容。
5. 未解决问题与 docs/development/deliveries/<编号>.md。

你的返回表示待主 Agent 审查，不代表已集成、已发布或全部验收通过。
~~~

主 Agent 可以把实现与只读审查交给不同子 Agent；审查任务需注明只读范围、被审提交和关注点。审查意见由主 Agent 判断并安排修复，不让多个审查者同时直接改同一实现文件。

## 6. 验收与最终交付

最终责任留在主 Agent，至少亲自核对下列证据：

- **权限边界：** 游客/账号双模式、两个普通账号、管理员的资源隔离，以及新增检索、引用、运行记录、后台任务接口都由服务端验证。
- **数据生命周期：** 旧知识库/消息保留，索引候选发布、删除竞态、文件清理、模型绑定与密钥延续符合指南。
- **真实性：** 02 的基线/候选采用可比较条件；04 的来源来自实际工具结果；05 的耗时/用量无伪造；06/07 的恢复能力不超出验证范围。
- **集成版本：** 子 Agent 的提交已经按依赖集成，必要测试针对同一最终代码版本完成；真实模型与线上验证未执行时如实列出，不能借用别的版本的报告。
- **交付完整：** README、契约、ADR、评测和部署说明反映实际状态；源码提交推送到用户的 ExoBrain 仓库，实际远程提交经过核对。
- **发布状态：** 按实际授权承担发布，沿用已有授权不重复询问。代码已推送、候选已验证和生产已部署分别据实说明，部署前不把已受理任务等同于已上线。

最终给用户简洁列出：完成的任务编号、关键行为变化、实际提交、测试/评测证据、线上状态与仍存在的限制。任务台账保留详细交接信息，用户无需逐个追问子 Agent 的完成情况。
