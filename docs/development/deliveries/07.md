## 2. 队列、幂等与租约

- 提交：用户消息、固定历史快照与排队任务在**同一事务**里写入；返回 `runId` + `runStatus=QUEUED`（重复提交同一幂等键返回原 message/run 并带 `idempotentReplay=true`）。JVM 事件只是唤醒提示，进程重启后仍由 `exobrain_chat_run_job` 恢复。
- 幂等：`(actor, session, key)` 唯一约束；相同键不同内容按设计拒绝；不按问题文本去重。
- 领取：worker 短事务领取（`FOR UPDATE SKIP LOCKED` 风格），带租约与 fencing；模型调用不占数据库事务；每个检查点续租，租约丢失抛 `RunLeaseLostException`，旧 worker 不能写回终态。
- 边界：全局 `max-queued`、每身份 `max-active-per-actor`、并发执行上限、幂等键长度上限；超过即拒绝，不把数据库当无限缓存。
- 授权：每次开始与关键步骤重新走 `ResourceAccess` / 运行守卫；账号停用、会话撤销、助手或知识库权限变化、模型停用都不会因已入队而绕过。
- 状态：`QUEUED / RUNNING / SUCCEEDED / FAILED / CANCELLED`（+ 05 的中断语义 `INTERRUPTED`）；终态幂等且不可被迟到事件覆盖。
- 副作用：不自动重放未知结果的外部调用；运行中取消是协作式停止，已发出的外部请求可能无法撤回。**不承诺 exactly-once。**

## 3. 迁移与回滚

- `20261017-07-durable-runs.sql` 增量、可重复执行，前置检查 `exobrain_run` / `chat_session` / `exobrain_user` 是否存在；不改写既有迁移，不写 GRANT（授权由 08 统一，见第 7 节）。
- 回滚：先停 worker（`app.runs.enabled=false` 或回滚旧镜像）→ 确认没有 `QUEUED/RUNNING` 遗留（把未开始的标记为 `CANCELLED`、运行中的按租约超时置 `INTERRUPTED`）→ 再回滚应用。旧版本不看这张表，但**新旧 worker 不得同时运行**，否则同一提交会被执行两遍。
