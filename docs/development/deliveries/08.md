### 2.4 CI 工作流（静态校验，**未真实执行**）

- YAML 解析校验通过：`jobs=['checks']`、`steps=13`、`permissions={'contents': 'read'}`、`runs-on=ubuntu-latest`。
- 步骤顺序符合要求：单元 profile → 真实 PostgreSQL 集成 → `npm ci` → 前端 lint → 游客构建 → 账号构建。
- 数据库服务容器：`pgvector/pgvector:pg17`，`--health-cmd pg_isready`（5s 间隔、24 次重试）后再进入集成步骤；口令用 `openssl rand -hex 16` **每次运行随机生成**并 `::add-mask::`，通过 `$GITHUB_ENV` 提供 `EXOBRAIN_IT_JDBC_URL` / `EXOBRAIN_IT_USERNAME` / `EXOBRAIN_IT_PASSWORD` / `EXOBRAIN_IT_REQUIRE_DATABASE=true`，host 端口 `54329`（避开 runner 镜像预装的 PostgreSQL）。
  - 使用 `docker run` 而不是 `services:` 的原因：`services:` 的环境值由工作流静态求值，无法使用“上一步生成的随机口令”；健康检查、随机口令、端口隔离三项要求都由显式容器启动满足。
- 权限与安全：工作流级 `permissions: contents: read`，`checkout` 关闭凭据持久化，未引用任何 secret，未执行任何部署动作；外部 PR 得不到秘密，也没有写权限上下文。
- 失败产物：`if: failure()` 上传 `${{ runner.temp }}/check-logs/*.log` 与 `jchatmind/target/surefire-reports/*.txt|*.xml`，`retention-days: 7`，`if-no-files-found: ignore`；仅这两类路径，不会打包 `.idea/`、`.claude/`、本机配置或私有语料。另收集 PostgreSQL 容器日志用于排查。
- **未执行**：本机没有 GitHub Actions 运行器，无法真实触发该工作流；这里只有静态结构校验，不能声明“CI 通过”。
