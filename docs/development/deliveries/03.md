## 3. 协议实现说明（与契约的差异）

- `RetrievalEnvelope.schemaVersion = 1`；`status ∈ {OK, NO_MATCH, UNAVAILABLE}`；非 OK 必须没有 hits（构造器强制）；`OK` 必须至少一个 hit。`errorCode` 为安全固定码（`NO_INDEXED_CONTENT`/`NO_MATCH`/`MODEL_BINDING_UNAVAILABLE`/`EMBEDDING_UNAVAILABLE`/`INDEX_UNAVAILABLE`/`INDEX_INVALID`/`INVALID_REQUEST`/`KB_NOT_ALLOWED`/`RETRIEVAL_UNAVAILABLE`），不含服务商原始异常。
- `citationId = retrievalId + ":" + rank`，`rank` 从 1 开始，`metric` 固定 `"l2"`，`distance` 有限非负（非有限/负值 → `UNAVAILABLE(INDEX_INVALID)`，不伪造数字）。`retrievalId` 每次调用新生成。
- `indexVersion`：`legacy-title-v1` / `body-v1`。`indexRevision` 是 `exobrain_index_revision.id`；**唯一差异**：legacy 数据没有发布记录，此时返回占位值 `"legacy-unversioned"`（不是伪造的版本号，04 不能拿它做版本比较）。这一点需要 04 与 08 知悉。
- `SourceLocation.sourceHash/startLine/endLine` 在 legacy 行上为 `null`（JSON 里保留 null 字段），`headingPath` 为空数组（legacy 行没有存过标题，不能编造）。
- 授权：调用方必须显式传入授权判断（`Predicate<String> maySearchKb`），服务在解析模型绑定、调用向量服务与查询向量**之前**执行；拒绝时抛 `RetrievalAccessDeniedException`（访问失败），不返回信封，也不把无权 KB 的名称/片段/数量/距离写进响应或日志。账号工具的实际围栏仍是运行时的 `ScopedToolCallback` + runtimeGuard（工具把“只检索本次调用参数里的那个 KB”作为显式判断传入）；演示工具传入公开白名单判断。
- SQL 在排序与 limit 之前限定 `kb_id` + 活动 `revision_id`；legacy 库只读 `revision_id IS NULL`。查询只在一个 KB 内进行，不跨模型比较距离。
- 工具输出：`KnowledgeTool(kbsId, query)` 与演示工具统一返回 `RetrievalEnvelope` JSON（没有“一半 JSON、一半无来源字符串”）。`RagService.similaritySearch` 保留为 `@Deprecated` 过渡适配（映射为片段正文；不可用时抛异常），仓库内已无生产调用者。
- 配置：`app.retrieval.top-k`（默认 3，夹取 1–10）、`app.retrieval.max-distance`（**默认 null = 未启用**，未校准前不使用任何相似度百分比，也不用 `1 - distance` 冒充置信度）、`app.retrieval.chunk-target-estimated-tokens`（默认 640，夹取 512–800）、`chunk-overlap-estimated-tokens`（默认 80，夹取 64–100）、`max-chunk-characters`（默认 4096）。

## 6. legacy 与 body 的行为差异、未重建旧库的表现

| 维度 | `legacy-title-v1`（无状态行且已有 chunk） | `body-v1`（新库 / 已发布版本） |
| --- | --- | --- |
| Embedding 输入 | 章节标题 | 标题路径 + 正文 |
| chunk 内容 | 章节正文（一个标题一块） | 按预算切出的正文片段（段落成组、带重叠） |
| `revision_id` / `index_version` | NULL / NULL（新写入也不再打标，保持基线行形状） | 版本 id / `body-v1` |
| `metadata` | NULL | 受控 JSON（标题路径、行号、源 hash、文档名） |
| 来源位置 | 全部 NULL，界面只能打开整份文档 | `startLine/endLine` + `sourceHash` 可核验 |
| 检索范围 | `revision_id IS NULL` | 状态行指向的那个已发布版本 |
| 新上传 | 继续写 legacy 行（不静默切换） | 合并进新版本：未变化文档在库内复制，新文档重新切块 |

未重建旧库的表现：查询照常工作（标题语义、无来源位置），`indexVersion` 返回 `legacy-title-v1`，`indexRevision` 返回
`legacy-unversioned`；上传新文档不会改变这个结论；只有显式重建（`RetrievalIndexService.rebuild`）才会切换，切换时旧版本
标记 SUPERSEDED 并保留（不删除旧向量），失败则保持旧索引可用。**未重建的库不会在启动时自动重建，也不会自动付费重算。**

### 给 06（持久化导入）

- 复用接口：`retrieval.RetrievalIndexService`
  - `resolveScope(kbId)` → `IndexScope(indexVersion, revisionId)`：KB 当前策略与活动版本。
  - `prepareRebuild(kbId, List<SourceDocument>)` / `prepareDocument(kbId, SourceDocument)`：**只切块、不写库、不调外部服务**。
  - `embedCandidate(candidate)`：调用 KB 绑定模型生成向量；**必须在数据库事务之外调用**。
  - `publish(candidate)`：短事务，重校验后原子切换；在已有事务里调用会加入该事务（上传路径就是这样）。
  - `rebuild(kbId, documents)`：prepare→embed→publish，失败登记一条 FAILED 版本且不改活动版本（离线/任务化重建用它）。
  - `cleanupSuperseded(kbId, keepNewest)` / `refreshActiveRevision(kbId)`；`IndexPublisher.rollback(kbId, revisionId)` 回滚。
- 竞态约束（发布时在事务内再次核对，任一不满足即拒绝，旧索引保持可用）：
  1) 候选文档集合必须与线上 `document` 集合完全一致（构建期间上传/删除都会让候选失效）；
  2) 候选覆盖的每个文档都要有 chunk（自身或从 `baseRevisionId` 复制），`baseRevisionId` 必须仍是当前活动版本；
  3) KB 绑定的向量模型必须与候选记录的一致；
  4) 发布持有 `knowledge_base` 行的 `FOR UPDATE`（与 KB 删除互斥，并串行化同库发布）。
  因此**同一 KB 的并发上传可能让其中一个候选过期**：任务化导入应重试（重建候选），不要试图跳过校验。
- 迁移：`deploy/migrations/20261017-03-body-index.sql` 是 06 的表结构基线，不要另建一套状态表。

## 9. 未解决的限制

1. **上传仍是长事务**：文档记录、文件路径写入、候选构建、Embedding 与发布在同一个上传事务内（发布本身是短事务，但会加入它）。
   期间持有 KB 行锁与文档行；重试体验差，超时或失败需要用户重传。任务 06 负责改造成持久化导入 + 短事务。
2. **同一 KB 的并发上传可能失败一次**：候选文档集合过期会导致发布被拒（“请重试”）。没有自动重建候选的重试循环。
3. **未校准的拒绝策略**：`max-distance` 默认关闭，所以“资料不足”目前只在空索引或空结果时返回 `NO_MATCH`；阈值需要 02 的开发集校准后启用。
4. **legacy 库不自动升级**：未重建的库继续只有标题向量与空位置；没有面向管理员的重建入口/脚本（本任务的 `rebuild` 只有服务接口与测试调用）。
5. **切块预算只是估算**：单位是保守的字符估算（CJK≈1、其余 2 字符≈1），不是 tokenizer 精确计数；换模型或启用精确 tokenizer 需要重新评估预算并换 `indexVersion`。
6. **表格按行切分**：基线未注册 flexmark `TablesExtension`，表格是普通段落文本；超长表格按行有界切分（可能把表头与部分数据行分到不同 chunk），来源范围仍然准确。
7. **没有增量索引**：一次发布覆盖整个 KB；重建要重新对所有文档调用 Embedding（未变化文档只在“单文档上传”路径里复制向量）。
8. **未做的跨库/多 KB 检索**：一次调用只查一个获准 KB（符合契约 §2），跨库组合留给运行时。
9. **`indexRevision = "legacy-unversioned"`** 是占位标识，不是版本号；如果 04 需要更严格的类型区分，需要一起修订契约。
