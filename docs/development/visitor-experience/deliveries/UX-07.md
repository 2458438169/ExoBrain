## 测量方法与逐次数据

- 环境：本机 Chrome（`playwright-core` `channel=chrome`，headless），视口 1366×900；
  CDP `Network.emulateNetworkConditions` 5 Mbps 下行 / 1 Mbps 上行 / **150 ms RTT**，
  `Emulation.setCPUThrottlingRate` **4×**；静态服务开启 gzip（与线上 nginx 一致）。
- 真实后端：本机隔离库 `exobrain_ux02` 上运行的本仓库构建（本地 jar，端口 18080），
  静态服务把 `/api`、`/sse` 转发到它，所以"按钮可用"包含真实的 `/api/demo/agents` 返回，
  不是用一个永不就绪的假接口测。
- 每个版本 **冷缓存 10 次 + 热缓存 10 次**（热缓存 = 同一浏览器上下文先真实访问一次，再测下一次导航），
  记录 TTFB、FCP、LCP、骨架出现、**推荐问题按钮可点击**、首屏 JS 压缩字节数。
  失败与超时保留在原始 JSON 里（本轮 0 失败）。

## 未达标项与下一步

1. **首屏 JS 294 KiB > 250 KiB**。剩余重量在入口 chunk 的 antd 核心与 `react-dom`。
   需要方向（未做，需确认视觉影响）：把公开首页外壳（顶栏/提示条/标题排版）换成原生元素，
   让 `antd` 只在账号工作区与阅读区加载；或把 `ConfigProvider` 的主题注入延后到首屏绘制之后。
   只把文件拆得更碎不会减少字节数，因此没有用拆 chunk 的方式去"凑"预算。
2. **构建产物仍有 >500 kB 的 chunk 警告**（阅读区与知识库视图，按需加载，不影响首屏）。
3. `ui/tailwind.config.js`（他人的 sakura 主题，且引用了未跟踪的 `ui/preview.html`）与
   `ui/preview.html` 仍未提交，本轮未改动。
4. 未在生产注入或测量：本轮数字全部来自本机隔离环境；线上冷/热对照需要在发布后用同一脚本复测，
   并在发布回执里记录真实公网数字。
5. 连续部署前后的旧页面加载（旧 hash chunk 失效）没有专门演练；当前策略是
   `hash` 资源长期缓存 + HTML `no-cache`，发布时保留上一版静态资源目录。
