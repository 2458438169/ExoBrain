## 实际修改与解决的问题

1. **一键开始**（E01）
   - 首页只保留一个明显主行动：第一个推荐问题是一张 `doodle-card` 主入口，另外两个推荐问题是一行式紧凑按钮（不占三张大卡片）。
   - 点击推荐问题直接创建会话并进入聊天页，把问题作为首条发送意图交给统一发送协调器；**不再先填输入框**。
   - 每个按钮的次级文案写明「直接提问 / 点击问题会立即发送，不需要再点一次确认」。
2. **手机首屏聚焦**（E07）
   - 主区改为「标题 + 一句用途 + 主按钮 + 两个紧凑入口 + 输入区」，390×844 首屏可见主按钮（底部 372px）与至少一个具体问题（底部 424px）。
   - 输入区用 `env(safe-area-inset-bottom)` 留安全区。
3. **弱化首次无历史的空记录区域**
   - `ChatTabContent` 的空状态从「大图标 + 两行占位」改为一句说明，只在真正没有记录时出现。
4. **助手未就绪的状态与重试**
   - 助手目录读取失败或为空时，首页显示可理解的提示 + 「重试」（`refreshAgents`），入口按钮同时禁用，避免点了没反应。
5. **统一发送协调器**（contracts §4）
   - `AgentChatView` 内只有一个提交函数 `sendIntent`：生成/复用幂等键 → 提交 → 受理成功统一收尾（清首条自动发送标记、记录 `runId`、消费终态重放）→ 失败只保留意图、不换键。
   - 首页推荐、「亲自试一试」、手动发送、相关追问四条入口全部汇入它；没有新增自动提交 Effect。
   - 同一个意图在提交过程中被重复触发（快双击、连按 Enter）时复用同一个 Promise，不并行提交。
6. **输入三态**
   - 可编辑草稿：等待期间仍可输入下一条（`Sender` 保持可编辑，只有发送按钮变成停止按钮）。
   - 可发送：`Enter` 发送、`Shift+Enter` 换行，占位与提示文案随连接/等待状态变化。
   - 可取消：已知 `runId` 时停止按钮调用真实 `POST /runs/{runId}/cancel`；`cancelRequested=true` 只显示「正在取消」，每 3 秒按真实运行状态收敛，终态才恢复输入。
7. **相关追问**
   - 最后一条回答下最多两个追问按钮，点击才发起新运行；等待期间禁用。
8. **刷新后的运行状态恢复**
   - 打开会话时读取运行摘要：仍有 `QUEUED/RUNNING` 的运行则恢复活动状态与可取消 `runId`，不重发、不新建意图。
