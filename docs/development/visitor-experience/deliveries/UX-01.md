## 实际修改与解决的问题

| 问题 | 改了什么 |
| --- | --- |
| 线上网关白名单缺少运行列表、运行详情、导入状态与取消路径，游客看到的是 Nginx HTML 404 | `deploy/nginx.conf` 的 `^~ /api/demo/` 白名单补齐 `chat-sessions/{id}/runs`、`runs/{id}`、`runs/{id}/cancel`、`documents/{id}/ingestion`；新增 `map "$request_method:$uri"` 规则，取消路径的 **非 POST 请求在网关层直接 405**，不进后端。附 `scripts/release/nginx-demo-runs.sh` 把差异幂等地应用到线上配置（备份 → 候选片段 `nginx -t` → 写入 → 生效值 `nginx -t`，失败自动回滚），`--check` 只打印 diff |
| 游客无法读取公开文档的导入状态（路径放行后仍被 `/api/demo/**` 兜底 403） | 新增 `DemoIngestionController`：`GET /api/demo/documents/{documentId}/ingestion`，授权用与读取原文同一条 KB 策略 `access::isPublicKb`（`DocumentFacadeService.requireReadableDocument`，只判定不读文件）。重试导入仍然只对账号/管理员开放，白名单里没有 `/retry` |
| 刷新后「没有答案的失败/取消/中断运行」无法挂回原问题 | `RunViews.PublicSummary` 增加可空 `triggeringMessageId` / `answerMessageId`，但**只在访客拥有该会话时**填充（`DemoRunService` 先判定 owner）；公开只读示例继续是 `null`。关联来自数据库字段，不按时间或位置猜测 |

## 接口变化（对前端）

- `GET /api/demo/chat-sessions/{id}/runs` → `{ runs: [{ runId, status, interrupted, … , triggeringMessageId, answerMessageId }] }`
  - 自己的会话：两个关联字段有值（答案尚未产出时 `answerMessageId` 为 null）。
  - 公开精选：两个字段恒为 null，沿用受限投影。
- `GET /api/demo/runs/{runId}` → `{ summary: { …同上… }, events: [...] }`
- `POST /api/demo/runs/{runId}/cancel` → `{ runId, status, cancelRequested, message }`；`cancelRequested=true` 只表示请求已登记。
- `GET /api/demo/documents/{documentId}/ingestion` → 与账号接口同结构（status / attempts / chunksDone / chunksTotal / errorCode）；无任务或不可读都是 404 JSON。
- 账号侧接口未改。
