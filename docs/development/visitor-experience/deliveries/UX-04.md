## 实际修改与解决的问题

1. **一轮问答成为一个阅读单元**（E03、tasks UX-04 第 1 步）
   - `AgentChatHistory` 先按消息角色构建「轮」：问题 → 该轮的 assistant 回答、tool 结果与 system 行。
   - 归组只依据服务端关联：`answerMessageId` → `triggeringMessageId` → 经过核对的 `metadata.runId`。缺失时保持独立展示，**不按时间或相邻位置猜测配对**。
   - 一轮只渲染一个执行过程摘要。
2. **紧凑来源入口**（E05、contracts §6）
   - 默认只有一行：「来源：文档 A · 文档 B · 共 6 处引用 · 查看全部依据」，用 `aria-expanded/aria-controls` 控制。
   - 展开后按 `documentId + sourceHash` 分组（同名文档的不同版本不合并），显示每组「本条文档 N 处片段」，每条引用保留编号、行范围/无精确位置、标题路径、节选、哈希、片段 ID 与索引版本。
   - 平铺的 6 条来源不再默认占满正文下方的空间。
3. **可展开执行过程**（tasks UX-04 第 2 步）
   - 摘要行只显示状态、服务端记录的耗时（`执行 7.8 s`）、排队耗时、工具调用次数、模型名与「查看过程」。
   - 展开后：真实时间线（序号、类型、耗时、状态，失败可重试）+ 本轮全部工具调用与工具结果（合并到同一处，不再散落在气泡上方）。
   - FAILED / CANCELLED / INTERRUPTED 的原因挂在问题附近（`RunOutcomeNotice`），没有答案消息的运行刷新后仍挂回自己的问题。
4. **运行读取三态**（E04、contracts §3）
   - 数据（`runs`）与请求状态（`runLoad / runError / runStale`）分开保存。
   - HTML 404、JSON 404、500、断网、响应格式错误 → 「执行记录暂时无法读取：<原因>」+ 重试；**不会**显示「没有执行记录」。
   - 成功的空结果才允许进入降级：每轮最多一次「这条历史消息没有执行记录」。
   - 消息自带 `runId` 但列表里没有该记录 → 「未能读取这条问题对应的执行记录」，不判定成旧历史。
   - 已有数据后后台刷新失败 → 保留数据 + 「执行记录尚未更新」。
   - 轮询只在 `document.visibilityState === "visible"` 时进行，终态停止；请求序号 + 会话比对丢弃过期响应。
5. **阅读位置**（contracts §7）
   - 打开历史会话：定位到最近一轮答案**开头**，展开的来源不会把答案挤出视野。
   - 首条完整答案到达且用户仍在跟随本轮：滚到答案开头（实测偏移 12–70 px），不再跳到来源底部。
   - 用户上滚 / 选择文字 / 展开来源：不改变位置；有迟到新回答时只在底部浮出「有新回答到达」，点击才跳到该答案开头。
   - 程序化滚动与用户滚动用时间窗区分，不用「距底部多少像素」单独判断。
6. **超长回答**（tasks UX-04 第 7 步）
   - 超过 1,200 字默认收起为最高 60vh 的容器（底部渐隐），按钮说明「展开完整回答（共 2,346 字）」，展开后不截断、可「收起回答」。
   - 完整 Markdown 始终保留，没有截断内容伪装成短答。
7. **只读示例**（tasks UX-04 第 9 步）
   - 复用同一阅读组件，但不传 `sessionId`：不读运行记录、没有取消、没有追问，只保留「亲自试一试」（会新建个人运行）。
8. **输入区与取消**（与 UX-03 共同实现）
   - 等待时 Sender 的发送按钮变成停止按钮，调用真实取消接口；取消登记后显示「正在取消」，终态由运行状态确认。
9. **无答案运行的活动状态**
   - 打开会话时读取运行摘要：仍在 QUEUED/RUNNING 的运行会恢复活动状态与可取消 `runId`（刷新不重发）；无答案且已终态的运行把原因挂在问题下。
