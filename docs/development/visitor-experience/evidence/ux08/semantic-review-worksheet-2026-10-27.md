## Q06 [boundary] SUCCEEDED

**问**：网络不好，我重复点了发送，会运行两次吗？

**期望**：['02_engineering_cases: 案例一（幂等键，最多执行一次；不是外部调用 exactly-once）']（上限 350 字）

**答**（278 字，2 条来源）：

```
不会跑两次：重复提交会被幂等去重，只保留一次运行 [1]。

- 每次「新的提问」会带一个唯一幂等键，服务端按 `(身份, 会话, 幂等键)` 去重；重试和重连复用同一个键，同一个键再次到达时不再新建运行，而是返回原来那次运行的 `runId` 和状态 [1]。
- 提交在同一个事务里完成（写用户消息、固定历史快照、创建运行、入队）；同键但内容不同会被直接拒绝，避免拿旧结果冒充新请求 [1]。
- 边界：这保证的是「同一会话的同一提交意图最多执行一次」，不等于对外部调用的 exactly-once —— 模型或第三方请求本身仍可能被重复发出 [2]。
```

**来源 [1]** 02_engineering_cases.md L8-22

```

9| 会出现两条用户消息、两个模型调用、两笔费用，甚至两条不同的回答挂在同一个问题上。
10| 
11| **方案**：把「一次提问」变成带唯一键的提交意图，服务端按 `(身份, 会话, 幂等键)` 去重。
12| 
13| - 前端为每个「新的提问意图」生成一个键，重试与重连复用同一个键，只有用户明确问下一个问题才换键。
14| - 提交在一个事务里完成：写用户消息、固定历史快照、创建运行记录、入队。同一个键再次到达时不再新建运行，
15|   而是返回原来那次运行的 `runId` 与状态。
16| - 同一个键但内容不同则直接拒绝，避免拿旧结果冒充新请求。
17| 
18| **验证结果**：真实 PostgreSQL 集成测试断言同键并发只产生一次运行、返回同一个 `runId`；同键不同内容返回冲突。
19| 真实浏览器里丢弃首个响应后手动重试，数据库仍然只有一个运行、一条用户消息、一次模型调用。

22| 工具调用、模型请求本身仍然可能被重复发出，系统只保证结果写入与终态是唯一且受校验的。
```

## Q07 [boundary] SUCCEEDED

**问**：点击取消之后模型又返回了，会发生什么？

**期望**：['02_engineering_cases: 案例二（fencing、迟到答案整笔回滚）']（上限 350 字）

**答**（383 字，1 条来源）：

```
**结论：迟到的回答不会进会话，运行终态仍是已取消 [1]。**

- 取消是协作式的：运行中的取消只登记 `cancel_requested`，检查点在下一步之前停止发起新的工具或模型调用，最终记为 `CANCELLED / CANCELLED_BY_USER` [1]。
- 写答案要同时满足「任务行仍是 RUNNING」和「fencing 未被接管」两个条件，且答案消息与 `answer_message_id` 同事务写入；不满足就整笔回滚，迟到的内容一个字都不留 [1]。
- 验证过的场景包括 18 秒模型调用配 10 秒租约：取消后终态为 `CANCELLED`，迟到响应不追加答复 [1]。

边界：取消不撤回已经发出的外部请求，也不承诺「立即停止」，界面显示的是「正在取消」，直到运行状态真正变成终态——所以不会出现「已取消 + 又有回答」[1]。
```

**来源 [1]** 02_engineering_cases.md L26-42

```
26| **问题**：取消是个协作式动作。已经发出去的模型请求无法撤回，几秒后它可能仍然返回一段完整答案。
27| 如果不加约束，这段时间里运行可能已经被标记为取消，而答案又被追加到会话里，用户看到「已取消 + 又有回答」。
28| 
29| **方案**：把「请求取消」和「运行终态」分开，并给每一次执行加 fencing 校验。
30| 
31| - 运行中的取消只登记 `cancel_requested`，检查点在下一个步骤前停止发起新的工具或模型调用，最终记为
32|   `CANCELLED / CANCELLED_BY_USER`。
33| - 每次领取任务都会让 `fencing_token` 前进。写答案时必须同时满足「任务行仍是 RUNNING」「fencing 未被接管」
34|   两个条件，答案消息与 `answer_message_id` 在同一个事务里写入；条件不满足就整笔回滚，迟到的内容一个字都不留。
35| - 取消与完成竞争、取消跨过心跳周期、重启遗留的 RUNNING 都有各自的判定，不会互相顶替。
36| 
37| **验证结果**：真实 PostgreSQL 用例覆盖三条路径：运行被标记中断后写答案必须抛出租约丢失并回滚；正常运行时
38| 答案与关联同事务落库；租约被接管后旧执行写不回任何内容。另有一条 18 秒模型调用、10 秒租约的用例，取消后
39| 终态为 `CANCELLED`，迟到响应不追加答复。
40| 
41| **边界**：取消不撤回已经发出的外部请求，也不承诺「立即停止」。界面显示的是「正在取消」，直到运行状态
42| 真正变成终态。
```
