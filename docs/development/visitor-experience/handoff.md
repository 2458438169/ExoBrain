# 可复制给实施 agent 的指令

用户可按自己的执行范围在下面补充提交、推送或发布要求。方案本身不发送消息，也不启动其他 agent。

## 交给一个 agent 完成第一批

```text
请执行 docs/development/visitor-experience/README.md 中的第一批访客体验优化。
先读 README.md、contracts.md、tasks.md 和 acceptance.md，再按 UX-01 → UX-02 → UX-03 → UX-04 → UX-05 → UX-06 推进。

目标是让简历访客在 https://exobrain.sharmoon.cc.cd/ 无需登录完成一键提问、短答案阅读、引用定位、执行过程查看和继续追问。
方案中的「待实施」条目不是已完成功能。请完成实际代码/配置/数据发布准备和验证，不停在再次写计划或仅编译通过。

开始时核对 HEAD 和未提交修改。主仓库已有其他 agent 的 UI 主题及发送修复；不得重置、清理、全量暂存或覆盖这些工作。ui/preview.html 不属于本任务。
旧 docs/public-demo 的三份资料受冻结测试约束，请按照方案新增 v2 资料与真实索引，不修改冻结基线来让测试通过。
所有发送入口共用稳定幂等键及终态收尾；保留 R1–R5 的取消、租约、心跳、fencing 和受保护写入语义。

按照每项任务的完成条件持续执行并交付 deliveries/UX-xx.md。真实流式属于第二批候选，先用测量决定，不用打字动画或假进度替代。
提交、推送与线上操作按我在本会话给出的授权执行。最终按 acceptance.md 报告实际提交、部署版本、验收证据和仍未完成的部分。
```

## 多个 agent 的分配建议

A 做 UX-01，B 做 UX-02，C 连续做 UX-03/04。A 与 B 可并行准备，C 先接收共享接口和内容约定。05/06 由集成负责人在候选版本上完成；前端共享文件始终只有一个直接编辑负责人。

### A：公开接口

```text
请领取 docs/development/visitor-experience/tasks.md 的 UX-01。
先读 README.md、contracts.md 中的 API/运行关联/读取状态约定，以及 evidence/baseline.md。
完成真实网关路径、游客取消入口、访客自身运行与消息关联。仓库已有 GET 规则而线上缺失，要交付能实际应用和验证的配置差异。
保留公开示例投影和跨访客隔离，不将完整账号投影暴露到游客接口。不要直接修改前端聊天组件。
交付代码/配置提交、真实代理后的成功与拒绝请求、关联字段样本及 deliveries/UX-01.md，供前端与最终发布集成。
```

### B：演示资料与索引

```text
请领取 docs/development/visitor-experience/tasks.md 的 UX-02。
先读 README.md、contracts.md 的数据版本/引用约定，以及冻结资产测试。
新增 v2 公开资料、清单与短答提示词，修正 README/架构/贡献说明的过时描述；保持旧三份资料与原评测快照逐字节不变。
通过产品上传与导入队列构建真实正文索引，验证来源定位、内容准确与个人贡献边界，准备三个真实只读示例。
保持公开 Agent ID，准备新旧 KB、提示词、公开范围与索引的明确切换/回退清单。不要把改了文档文件等同于线上已更新。
交付推荐问题、真实核对结果和 deliveries/UX-02.md；不要编辑前端共享文件。
```

### C：首页与聊天阅读

```text
请连续领取 docs/development/visitor-experience/tasks.md 的 UX-03、UX-04。
先读 README.md、contracts.md 和 UX-01/02 的交付。你是 AgentChatView、AgentChatHistory、EmptyAgentChatView 及相关 API/types 的统一前端负责人。
接收已有主题与 R2 修复，完成一键体验、统一发送、可用的取消/恢复、短答案阅读、紧凑来源、可展开运行过程和正确滚动行为。
重点验证首次响应丢失后同键重试与 SSE 重连、终态重放、无答案运行刷新恢复、接口 404 不误报未保存。
参考 evidence 中的真实桌面/手机截图，按 acceptance.md 检查 320/390/768/1366px 和移动键盘。不要只提交静态页面。
分别交付 deliveries/UX-03.md 与 deliveries/UX-04.md，以及对应浏览器和构建证据。
```

### 集成负责人：首答性能与发布验收

```text
请领取 docs/development/visitor-experience/tasks.md 的 UX-05、UX-06。
先读取 01–04 的实际提交与交付记录，把待发布代码、网关、资料、索引与提示词组合成明确候选版本。
按 acceptance.md 用真实阶段事件、真实浏览器和模型服务测量首答，完成短答/重复工作等有依据的优化。提示词和前端改动交回原负责人协调合并。
若要实施流式，先落实 contracts.md 的部分结果、取消/租约丢失和最终提交协议；不可绕过现有守卫。
执行端到端矩阵，准备可复现发布包和回退说明。按用户在本会话的发布授权操作；上线后必须用新游客实际提问并检查引用定位与运行详情。
提交 deliveries/UX-05.md、deliveries/UX-06.md，明确每个硬要求与性能目标的实际结论，不把未运行或环境受阻记为通过。
```
