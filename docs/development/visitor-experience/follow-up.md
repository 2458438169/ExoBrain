## UX-07：从简历打开链接到能提问（P1）

已观察到账号页一次冷加载 DOMContentLoaded 35.206 s，其中入口 JS 下载 32.838 s，解压前 460,268 bytes、解压后 1,449,534 bytes；同页缓存后 0.892 s。公开页第一次导航也超时，但没有完整冷加载分段，不能拿账号页数字代替公开页。公网已经压缩；源站 HEAD 的响应头不足以证明公网没有压缩。

本任务目标是首次访客能尽快看懂用途并点击推荐问题。首屏画出骨架和真正能提交问题分别计时，不能把加载占位当成可用。

实施步骤：

1. 先对 `/chat`、`/admin/` 各录 10 次冷缓存和 10 次热缓存：导航开始、HTML TTFB、LCP、推荐按钮可用、资源下载与主线程执行。记录浏览器、网络位置、带宽/RTT/CPU 模拟参数、资产 hash；失败与超时保留。另留真实网络结果，不和模拟数据合并。
2. 输出两个构建的入口依赖图与实际首屏请求集合。代码入口是 `ui/src/App.tsx`、`JChatMindLayout.tsx`、`AccountWorkspace.tsx`；核对工作区页面、Markdown 渲染、文档抽屉、管理表格和图标的进入路径。先证实哪些模块进入首屏，不能仅凭静态 import 就声称它们都被打包。
3. 优先按路由与重组件做 `React.lazy` / `Suspense`。公开首页只依赖说明、问题入口与输入组件；会话、原文预览和账号管理按实际访问加载。必要时按 hover/focus/idle 预取下一步，但低速网络不抢占当前首屏资源。
4. 首屏等待和 chunk 加载失败必须可读、可恢复。恢复时保留当前问题、草稿和幂等意图；不能用整页自动刷新掩盖失败，也不能因为加载恢复再次 POST。继续复用已有发送协调器。
5. 核对 hash 资产的长期缓存、HTML 的更新策略及双构建 base。发布必须原子切换、保留旧版本 chunk，避免已打开页面在新部署后加载旧 hash 得到 HTML 404。只有实测表明有缺口时才改压缩/缓存。

验收目标（目标值，不是当前成绩）：在固定 5 Mbps / 150 ms RTT / 4× CPU slowdown、冷浏览器缓存下，公开首页 10 次中按钮可用 p95 ≤ 5 s，热缓存 p95 ≤ 2 s；首屏 JS 的实际压缩下载总量 ≤ 250 KiB。若基线显示该预算无法满足，交付依赖成本与实测差异，不能只把文件拆成多个 chunk 来宣称达标。登录页单独统计。

必须回归：真实新游客第一次点击只创建一运行；会话深链刷新；`/admin/` 登录与鉴权；原文抽屉首次打开；连续部署前后加载旧页面；离线/chunk 失败恢复；320/390/768/1440 布局与键盘焦点。必要检查沿用 lint、TypeScript、状态测试和双构建，不为简单样式镜像实现编写测试。

## UX-08：让简短答案与具体来源一致（P1）

当前机械编号映射已有校验，但模型仍会选错支撑片段。固定 12 问最新组：11 次运行成功、9 条内容可用；Q03 将评测放在只含权限/模型/CI 的来源下，Q09 将边界说明指向产品功能段落。另一问的协议残片被拒绝。不能用「hash 与行号正确」代替语义准确，也不能只挑成功答案计算整体质量。

实施步骤：

1. 保留现有 12 问并扩展到至少 30 个预先固定的问题，包含三条首页入口的改写问法、资料不足、权限、取消与重启边界。标注每个关键事实能由哪些原文范围支持；真实请求前冻结题单，测试后不按结果换题。
2. 先只调整答复组织：推荐题用一句结论和最多三项代表能力，每一项选一条直接支撑的片段；跨章节的复合句拆开。维持 `[n] → citationIds 第 n 项` 契约，禁止以最后一个检索 rank 当编号。记录助手提示词及工具 schema 的 hash。
3. 如果持续出现编号理解错误，再小规模比较显式来源标记或结构化「陈述 + 来源 ID」协议。任何服务端转换只依据本次已验证的 ID，不能根据文档名称或正文关键词猜引用，也不能偷偷修改已保存历史答案。
4. 将协议残片和语义错引分开评估。考虑一次有界格式重试前，先统计失败率、额外时延与调用成本；若实施，必须经过取消/租约检查、记录真实重试事件，并保持原有提交意图，不创建第二条用户消息。没有测量前不加入自动重试来掩盖失败。

建议门槛：固定 30 问中至少 28 条的关键事实与实际引用范围逐条相符；所有引用编号都能对应已授权来源；三条推荐题均在 200–350 中文字符左右，来源可真实打开定位；失败、拒答和超时保留为独立分母。首答目标 p50 ≤ 6 s / p95 ≤ 10 s，未达标时给出模型、检索、网络及 UI 分段，不虚构达成。

精选只展示人工复核合格的真实运行，并清楚作为历史示例。它们不代表随机实时回答都达到同样质量。不得给不正确的引用补元数据，不得把合成回答或改写后的历史答案发布为真实成功样本。
